# 第 4 页：什么是中间件

* **核心作用**：
  * 中间件主要用于**拦截或过滤**应用的 HTTP 请求，并进行必要的业务处理；
  * 可完美解决**验证时机**和**冗余代码**问题。
* **命令行指令**：
  ```bash
  # 基础命令生成中间件
  php think make:middleware Check

  # 在指定应用下生成中间件
  php think make:middleware weibo@Check
  ```
  * 执行后会在 `app/weibo/middleware` 目录下生成一个 `Check` 中间件。

---

# 第 5 页：中间件的执行流程

```text
[客户端提出请求 Request]
         │
         ▼
    [前置中间件]   ──> (加入拦截或过滤脚本)
         │
         ▼
  [服务器响应 Response] ──> (完成方法脚本执行后需要完成的工作)
         │
         ▼
    [后置中间件]
         │
         ▼
    [结束调度]     ──> (完成收尾工作，不能输出信息)
```

# 第 6 页：哪些请求会被拦截？——四种中间件

* **全局中间件**：适用于所有请求 —— 在 `app/middleware.php` 中注册
* **应用中间件**：适用于指定应用的所有请求 —— 在 `app/应用/middleware.php` 中注册
* **路由中间件**（课堂编写重点）：适用于某条或某组路由 —— 在定义路由规则语句中注册
* **控制器中间件**：适用于某个控制器的某些方法 —— 在控制器中定义属性

# 第 8 页：中间件相关配置文件（配置 + 注册）

### 1. 配置文件：`config/middleware.php`
* **功用**：配置中间件文件的别名、优先级。
```php
<?php
// 中间件配置
return [
    // 别名或分组
    'alias'    => [],
    // 优先级设置，此数组中的中间件会按照数组中的顺序优先执行
    'priority' => [],
];
```

### 2. 注册文件：`app/middleware.php` 或 `app/应用/middleware.php`
* **功用**：注册中间件文件。
```php
<?php
// 全局中间件定义文件 / 应用中间件定义文件
return [
    // 全局请求缓存
    // \think\middleware\CheckRequestCache::class,
    // 多语言加载
    // \think\middleware\LoadLangPack::class,
    // Session初始化
    \think\middleware\SessionInit::class,
];
```

# 第 9 页：总结

* **配置文件**：`config\middleware.php`
* **注册文件**：`app\middleware.php` 或 `app\应用\middleware.php`
* **中间件本体**：`app\middleware\X.php` 或 `app\应用\middleware\Y.php`

> **区分规则**：
> * 文件名包含 `middleware`，是**配置或注册文件**；
> * 文件夹名包含 `middleware`，是**包含中间件文件的文件夹**。

# 第 10 页：中间件文件的定义

* **核心规则**：
  1. 中间件的入口执行方法必须是 `handle` 方法，而且**第一个参数是 `Request` 对象，第二个参数是一个闭包**。
  2. 中间件 `handle` 方法的**返回值必须是一个 `Response` 对象**。

### 基础代码骨架：
```php
<?php
namespace app\middleware;

class Before
{
    public function handle($request, \Closure $next)
    {
        // 添加中间件执行代码

        return $next($request);
    }
}
```

---

# 第 11 页：前置/后置中间件

> 中间件是在请求具体的操作之前还是之后执行，完全取决于中间件的定义本身（与闭包 `$next` 的调用顺序决定）。

### 1. 前置中间件
```php
<?php
namespace app\middleware;

class Before
{
    public function handle($request, \Closure $next)
    {
        // 添加中间件执行代码（在执行控制器之前）

        return $next($request);
    }
}
```
* **功用**：表单验证、权限控制、参数过滤判断等，把请求计入日志。

### 2. 后置中间件
```php
<?php
namespace app\middleware;

class After
{
    public function handle($request, \Closure $next)
    {
        $response = $next($request);

        // 添加中间件执行代码（在执行方法脚本后）

        return $response;
    }
}
```
* **功用**：在方法脚本执行后需要完成的工作，如请求完成后把请求的耗时等信息计入日志；
* **注意**：如果前置中间件脚本中有跳转到其他方法的脚本，后置中间件会得不到执行。

---

# 第 12 页：结束调度

中间件支持定义请求结束前的回调机制，只需在中间件类中添加 `end` 方法：
```php
public function end(\think\Response $response)
{
    // 回调行为
}
```
* **注意**：在 `end` 方法里面**不能有任何的响应输出**，因为回调触发的时候请求响应输出已经完成。
* **功用**：需要的收尾工作，**一定会做**（后置中间件可能因为请求被拦截而被跳过），可以用于记录最终请求的详情日志（耗时、状态码、关键数据等）。

* **注册为应用中间件**：在 `app\应用\middleware.php` 中注册（仅用于本应用的中间件文件）。

# 第 16 页：创建自定义中间件

### 3.2.1 创建自定义中间件
ThinkPHP 提供了命令行工具快速生成中间件骨架。
* **步骤**：
  1. 打开命令行终端，切换到项目根目录，执行以下命令：
     ```bash
     php think make:middleware AuthMiddleware
     ```
     执行成功后，会在 `app/middleware/` 目录下生成 `AuthMiddleware.php` 文件。
  2. 编写中间件逻辑，示例：检查请求是否携带有效的 Token。
* **说明**：
  * 中间件的入口执行方法必须是 `handle` 方法，而且第一个参数是 `Request` 对象，第二个参数是一个闭包；
  * 中间件 `handle` 方法的返回值必须是一个 `Response` 对象；
  * 代码写在 `$next($request)` 之前是前置中间件，反之是后置中间件；
  * `$next($request)` 表示“放行，把请求交给下一层（下一个中间件或控制器）”。

# 第 17 页：练习（AuthMiddleware）

* **任务**：在 `app/middleware` 中创建 `AuthMiddleware`，并完成以下要求：
  * 验证请求头中的 `Authorization` 是否存在；
  * 否则返回状态码 401 的 JSON 错误信息。

### 参考代码：
```php
<?php
namespace app\middleware;

use think\Request;
use think\Response;

class AuthMiddleware
{
    /**
     * 前置中间件：在控制器执行之前进行拦截
     */
    public function handle(Request $request, \Closure $next)
    {
        // 获取请求头中的 Authorization
        $token = $request->header('Authorization');

        // 模拟 Token 验证（后续将替换为 JWT 验证）
        if (!$token) {
            return json([
                'code'    => 401,
                'message' => '未登录或 Token 无效',
                'data'    => null
            ]);
        }

        // 允许请求继续执行
        return $next($request);
    }
}
```

# 第 22 页：TP 如何实现验证

* `think-validate` 是一个基于 PHP 8.0 的数据验证类库，最新版本已经从 ThinkPHP 核心独立出来单独维护更新，以优异的功能和突出的性能著称，提供了更优秀的性能和开发体验。使用 ThinkPHP 框架的话，无需额外安装会自动依赖。
* **主要特性**：
  * 基于 PHP8 和强类型实现
  * 内置丰富的验证规则
  * 支持验证器类、数组和链式方法定义验证规则
  * 支持验证场景和验证分组
  * 支持独立数据验证
  * 支持枚举验证
  * 支持批量验证
  * 支持抛出异常
* **架构建议**：对于简单的验证场景，可以直接在控制器中使用 `validate()` 助手函数；对于复杂或需要复用的验证规则，TP 推荐使用**验证器类**。

# 第 24 页：验证器的属性定义

### 代码结构：
```php
<?php

{
```

# 第 33 页：验证器的调用——异常处理，程序接管（推荐）

```php
<?php
namespace app\controller;

use app\validate\User;
use think\exception\ValidateException;

class Index
{
    public function index()
    {
        try {
            validate(User::class)->check([
                'name'  => 'thinkphp',
                'email' => 'thinkphp@qq.com',
            ]);
        } catch (ValidateException $e) {
            // 验证失败 输出错误信息
            dump($e->getError());
        }
    }
}
```
* **效果**：程序能友好捕获错误并返回格式化数据，而不是抛出系统崩溃页。

# 第 34 页：手动捕获异常

* `try`：包含要做的动作。
* `catch`：表示动作完成时候捕获的异常：
  * `ValidateException`：验证时捕获的异常；
  * `Exception`：其他全局异常。

```php
try {
    // 这里是主体代码
} catch (ValidateException $e) {
    // 这是进行验证异常捕获
    return json($e->getError());
} catch (\Exception $e) {
    // 这是进行异常捕获
    return json($e->getMessage());
}
```

# 第 35 页：验证过程的异常捕获分析

* **`try` 分支说明**：
  * `User` 是定义好的验证器；
  * `User::class` 返回类的完全限定名称字符串；
  * `validate()`：助手函数，第一个参数是验证器，当验证不通过返回 `false` 并抛出异常。
* **`catch` 分支说明（捕获异常）**：
  * `ValidateException` 是验证异常类；
  * `ValidateException $e` 是依赖注入，`$e` 实例化为一个异常对象。

# 第 39 页：在中间件中使用验证器类

将验证器类接入请求处理流程，除了在控制器中直接调用外，**更推荐在中间件中完成参数校验**，原因如下：
1. **控制器更专注**：控制器只负责业务逻辑，不掺杂校验代码；
2. **复用性更强**：同一个验证器可以在多个路由或分组中复用；
3. **职责更清晰**：中间件负责“拦截非法请求”，验证器负责“定义校验规则”，符合单一职责原则；
4. **便于扩展**：引入 JWT 后，可以在同一个中间件中先校验 Token，再校验参数。

# 第 43 页：实例 6 代码分析：调用验证器并挂载数据

```php
try {
    $json = file_get_contents('php://input');
    $data = json_decode($json, true);

    validate($validateClass)->scene($scene)->check($data);

    $request->validatedData = $data; // 核心：挂载校验通过的数据

    return $next($request);
} catch (ValidateException $e) {
    return $this->jsonData(400, $e->getMessage());
}
```
* **核心点**：校验通过后，把数据挂载到 `$request->validatedData`，后续控制器可直接使用，**避免控制器重复解析请求体**。

# 第 44 页：在路由中绑定验证中间件（实例 7）

```php
Route::group('sessions', function () {
    // 登录数据绑定中间件实施数据验证
    Route::post('', 'login')
        ->middleware(ValidateMiddleware::class, LoginValidate::class, 'login');

    Route::delete('', 'logout')->middleware(AuthMiddleware::class);
})->class(User::class);
```
* **说明**：
  * 在 `middleware(ValidateMiddleware::class, LoginValidate::class, 'login')` 中：
    * 第 1 个参数是中间件类（`ValidateMiddleware::class`）；
    * 第 2 个参数是验证器类（`LoginValidate::class`）；
    * 第 3 个参数是验证场景（`'login'`）。
  * 中间件的额外参数会按顺序传递给 `handle()` 方法的对应形参。
