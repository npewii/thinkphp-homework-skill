* **教师登录后**：查看自己的教学任务列表；

# 第 12 页：参数分组分析

### 参数分组原则

#### 1. 收纳到 `$params` 里的（业务查询参数）
* **包含字段**：如 `startTerm`、`endTerm`、`scoreStatus`。
* **规则**：这些参数用于模型拼接 SQL 的 `WHERE` 条件。推荐使用 `$request->only(['startTerm' => 0, ...])` 来提取，既起到了**白名单过滤**的作用，又能**设置默认值**，防止前端不传导致报错。

#### 2. 不需要收纳到 `$params` 里的（流程控制参数）
* **身份标识**：如 `teId`。用于权限隔离，需单独提取。
* **分页控制**：如 `limit`。决定了数据怎么切块，通常需要强制类型转换 `(int)` 防止前端传入恶意字符。

### 控制器方法对参数的分组实施代码
```php
// 1. 提取业务参数（使用 only 白名单过滤并设置默认值 0）
$params = $request->only(['startTerm' => 0, 'endTerm' => 0, 'scoreStatus' => 0]);

// 2. 提取身份和分页控制参数（默认从 Token 获取 teId 防止越权）
$teId = $request->get('teId', $request->jwtUser['uid']);
$limit = (int)$request->get('limit', 15);
```

# 第 13 页：控制器方法编程 Task.php/index（思路）

1. **参数分组与安全提取**：
   * **业务参数 (`$params`)**：由于 `startTerm`、`endTerm` 等参数用于数据库查询，推荐使用 `$request->only()` 提取并赋予默认值 0，既起到了白名单过滤作用，又防止了前端漏传参数导致 SQL 报错；
   * **身份与分页参数**：`teId` 决定了查谁的数据。为了防止越权，默认从 JWT Token (`$request->jwtUser['uid']`) 中提取当前登录者的工号；`limit` 属于分页控制参数，使用 `(int)` 强制转换，防止前端传入非法字符引发系统异常。
2. **业务逻辑流转**：将提取好的参数按顺序传入模型层的 `getTask()` 方法，获取封装好的分页数据。
3. **友好提示与异常兜底**：在返回数据前，判断 `total` 是否为 0。如果为 0，虽然 HTTP 状态码依然是 200，但通过自定义 `message`（如“查询成功，但暂无教学任务”）给前端更友好的提示。同时，使用 `try...catch` 捕获模型层可能抛出的异常，统一通过 `$this->error()` 返回规范的 JSON 格式。

# 第 14 页：控制器完整代码（Task.php/index）

```php
<?php
declare (strict_types=1);

namespace app\edu\controller;

use app\BaseController;
use app\edu\model\Task as ModelTask;

class Task extends BaseController
{
    /**
     * 显示资源列表
     * @return string json字符串
     */
    public function index()
    {
        try {
            // 步骤1：从请求中获取查询参数
            // 使用 only() 方法白名单接收，只取 startTerm、endTerm、scoreStatus 三个参数
            // 如果请求中没有传这些参数，则使用默认值 0
            $params = $this->request->only(['startTerm' => 0, 'endTerm' => 0, 'scoreStatus' => 0]);

            // 步骤2：从 JWT 认证信息中获取当前登录教师的工号 (te_id)
            // jwtUser 是 JWT 中间件解析后注入到 request 对象中的用户信息
            $teId = $this->request->jwtUser['uid'];

            // 步骤3：获取分页条数 limit
            // 从 GET 参数中读取 limit，默认为 15 条/页，并强制转换为整型，防止非法字符串
            $limit = (int)$this->request->get('limit', 15);

            // 步骤4：调用模型层方法执行教学任务查询
            // 传入教师工号、查询参数、分页条数，返回分页结果数组
            $taskRe = (new ModelTask)->getTask($teId, $params, $limit);

            // 步骤5：判断查询结果是否为空
            // 如果总记录数为 0，返回提示信息（仍然返回 200 状态码，属于正常查询结果）
            if ($taskRe['total'] == 0) {
                return $this->success(200, '查询成功，但暂无教学任务', $taskRe);
            }

            // 步骤6：查询结果非空，返回成功响应和教学任务数据
            return $this->success(200, '教学任务查询成功', $taskRe);

        } catch (\Throwable $th) {
            // 步骤7：异常处理
            // 如果异常没有设置错误码，则默认使用 500（服务器内部错误）
            $code = $th->getCode() ?: 500;

            // 返回错误响应，包含错误码和异常信息
            return $this->error($code, $th->getMessage());
        }
    }
}
```

# 第 15 页：辅助服务类：获取当前学年学期（TermTool.php）

* **使用场景**：当前未输入起始学年学期，就查询当前学年学期的教学任务。
* **编码规则分析**：
  * 假设当前是 2026 年 10 月，属于 2026-2027 学年的第 1 学期（秋季），编码可定为 `262701`。
  * 如果当前是 2026 年 5 月，属于 2025-2026 学年的第 2 学期（春季），编码为 `252602`。

### 代码实现：`app/service/TermTool.php`
```php
<?php
declare(strict_types=1);

namespace app\service;

class TermTool
{
    /**
     * 获取当前学年学期
     * @return int 当前学年学期
     */
    public static function thisTerm()
    {
        $startY = date('y');
        $month = (int)date('m');
        $termNo = '01';

        // 8月及之前属于上一学年的第二学期（春季学期）
        if ($month <= 8) {
            $startY = $startY - 1;
            $termNo = '02';
        }

        return (int)($startY . ($startY + 1) . $termNo);
    }
}
```

# 第 16 页：模型方法设计：Task.php/getTask（核心机制）

1. **链式调用的起点**：首先使用 `$this->with(...)` 预载入（Eager Loading）班级、教师和课程这三个 `belongsTo`（一对一/多对一）关联。这样不仅能一次查询中拿到所有需要展示的数据，还能避免后续在 `foreach` 循环中频繁查询数据库（即**解决 N+1 问题**）。
2. **关联条件过滤 (hasWhere)**：由于前端传入的是教师工号，我们需要通过 `hasWhere('teInfo', ['te_id' => $teId])` 将查询条件传导到关联的教师表。这在底层会生成 `EXISTS` 或 `IN` 子查询，是处理多表关联条件最优雅的方式。
3. **学期区间容错处理**：
   * 当 `startTerm` 和 `endTerm` 都为 0（即前端未传具体区间）时，通过 `TermTool::thisTerm()` 自动获取当前学期，并利用 `where()` 进行精准匹配；
   * 当传入具体区间时，使用 `whereBetween` 进行范围查询，满足跨学期统计的需求。
4. **分页参数透传**：在调用 `paginate()` 时，必须传入 `'query' => $params`。这样 ThinkPHP 在生成分页链接时会自动把前端的查询条件带在 URL 后面，防止翻页时条件丢失。
5. **数据结构重塑**：`paginate()` 返回的对象包含大量原始数据，不适合直接返回给前端。我们手动提取 `total`、`per_page` 等分页元数据，并通过 `foreach` 遍历数据集，从中挑出前端需要的少数字段（如 `ta_id`、`ta_te`），统一放入 `list` 数组。

# 第 17 页：分页查询 paginate 机制

* **隐式传递 page 参数**：ThinkPHP 的 `paginate()` 方法会自动识别请求 URL 中的 `?page=x` 参数，不需要我们手动提取 page 去计算偏移量。如果 URL 中没有传 page，框架会自动默认为第 1 页。
* **query 参数的重要性**：`paginate(['query' => $params])` 中的 `query` 是为了让分页对象在生成“上一页/下一页”链接时，能把前端原本的搜索条件（如 `startTerm=252601`）拼接到 URL 后面。如果不加，翻页时条件就会丢失，导致第 2 页查出的是全部数据。
* **越界处理**：如果用户手动输入 `?page=999` 导致越界，`paginate()` 返回的依然是合法的分页对象。`$task->total()` 依然是真实总条数，而 `$task->items()` 会返回空数组 `[]`。前端只需判断列表是否为空，无需后端特殊拦截。

# 第 18 页：`?->` 空安全运算符兜底机制

* **为什么要用**：当你使用 `with` 进行预载入时，如果数据库中存在**脏数据**（比如某门课程被删除了，但教学任务记录还在），`$value->courseInfo` 会返回 `null`。此时如果用 `->` 直接读取 `c_name`，系统会抛出致命错误（`FatalError`），直接返回 500。使用 `?->`，如果前面的对象是 `null`，后面的属性调用会静默终止，直接返回 `null`。
* **`??` 的配合**：`?->` 返回 `null` 后，通过 `?? '默认值'` 即可给前端提供兜底展示。比如 `$value->teInfo?->te_name ?? '未知教师'`，即使关联数据缺失，前端表格依然能正常显示，用户体验不会因为后台脏数据而崩溃。
* **主模型字段不要加 `?->`**：`foreach` 遍历出来的 `$value` 一定是一个模型对象（不可能为 `null`），因此 `$value?->ta_id` 是多余的，直接写 `$value->ta_id` 即可，避免代码阅读者产生误解。

# 第 19 页：模型代码设计：Task.php/getTask（前半部分）

> **关键要点**：
> 1. 需在 `task` 表增加字段（`ta_score`），存储当前教学任务成绩的录入状态：`0` —— 未提交；`1` —— 部分录入；`2` —— 已提交。
> 2. `hasWhere` 引出关联的条件，**必须在 `where` 之前调用**。
> 3. `$teId` 也是查询条件，故也要一起放入分页参数中。

```php
/**
 * 查询教学任务
 * @param int $teId
 * @param array $params ['startTerm', 'endTerm', 'scoreStatus']
 * @param int $limit
 * @return array 教学任务查询结果
 * @throws \Exception 查询不到抛出异常
 */
public function getTask($teId = 0, $params = [], $limit = 15)
{
    // 1. 构建基础查询链：预载入班级、教师、课程关联，并绑定教师工号与成绩状态条件
    $task = $this->with(['classInfo', 'teInfo', 'courseInfo'])
        ->hasWhere('teInfo', ['te_id' => $teId])
        ->where('ta_score', $params['scoreStatus']);

    // 2. 学年学期区间过滤
    if ($params['startTerm'] == 0 && $params['endTerm'] == 0) {
        // 2.1 前端未传区间时，通过工具类自动获取当前学期进行精准匹配
        $params['startTerm'] = TermTool::thisTerm();
        $task = $task->where('ta_term', $params['startTerm']);
    } else {
        // 2.2 前端传入了区间，使用 whereBetween 进行范围查询
        $task = $task->whereBetween('ta_term', [$params['startTerm'], $params['endTerm']]);
    }

    // 3. 组装分页附加参数（关键）：将 teId 合并入参数数组中
    // 确保前端翻页时，URL 中能自动保留 &teId=***，防止身份参数丢失
    $queryParams = array_merge($params, ['teId' => $teId]);

    // 4. 执行分页查询
    $task = $task->paginate([
        'list_rows' => $limit,
        'query'     => $queryParams
    ]);
```

```php
    // 5. 初始化统一的响应数据结构（标准的分页统计数据）
```

# 第 28 页：模型方法设计：Task.php/getTaskScore（优化设计分析）

1. **多级关联预载入**：使用 `with(['teInfo', 'classInfo.stus', 'scores', 'courseInfo'])`。注意这里包含了嵌套关联 `classInfo.stus`（先查班级，再查班级下的所有学生），以及独立的成绩关联 `scores`。这能一次性把页面需要的所有数据查出来，极大减少数据库连接次数。
2. **任务信息组装与空值容错**：在组装 `$task` 数组时，由于使用了多表关联，为了防止因为脏数据（如某门课的教师被删除了）导致系统抛出致命错误，使用空安全运算符 `?->` 并搭配 `??` 提供默认值（如“未知教师”）。
3. **核心性能优化（空间换时间）**：
   * **痛点**：如果在遍历学生时，每次都用 `foreach` 去遍历成绩集合寻找匹配项，时间复杂度将是平方级的 $O(N^2)$。如果班级有 50 人，就要比对 2500 次。
   * **解法**：我们先遍历成绩集合，以学号（`sc_stu`）为键，构建一个字典数组 `$scoresDict`。PHP 底层的数组是哈希表实现，查找时间复杂度为 $O(1)$。这样在后续遍历学生找成绩时，只需 `$scoresDict[$stu->stu_id]` 即可瞬间取出，将时间复杂度降至线性的 $O(N)$。
4. **嵌套数据遍历与数据兜底**：
   * 使用 `if ($taskRe->classInfo && $taskRe->classInfo->stus)` 进行防御性判断，防止班级下没有任何学生时引发遍历报错；
   * 遍历学生时，通过 `?? null` 兜底。如果该学生在字典中找不到成绩（即还没录入），则 `$stuScore` 为 `null`，后续的成绩字段也会自动输出为 `null`，保证前端表格不会错位或报错。

# 第 29 页：模型代码实现：Task.php/getTaskScore（前半部分）

> **避坑提示**：构建哈希字典时，取的是**成绩模型**的学号字段 `sc_stu`，而不是学生模型的字段 `stu_id`。

```php
/**
 * 获取教学任务的成绩
 * @param int $taskId 教学任务ID
 * @return array 包含任务信息与成绩列表的数组
 */
public function getTaskScore($taskId)
{
    // 1. 预载入多级关联查询
    $taskRe = $this->with(['teInfo', 'classInfo.stus', 'scores', 'courseInfo'])
        ->where('ta_id', $taskId)->find();

    if (!$taskRe) {
        throw new \Exception('教学任务编号错误', 404);
    }

    // 2. 组装头部任务信息（使用 ?-> 防止关联数据丢失引发空指针报错）
    $task = [
        'ta_id'     => $taskId,
        'ta_te'     => $taskRe->teInfo?->te_name ?? '未知教师',
        'ta_class'  => $taskRe->classInfo?->cl_name ?? '未知班级',
        'ta_c_name' => $taskRe->courseInfo?->c_name ?? '未知课程',
        'ta_c_type' => $taskRe->courseInfo?->c_type ?? '未知考试类型',
        'ta_c_exam' => $taskRe->courseInfo?->c_exam ?? '未知考试方式'
    ];

    // 3. 核心优化：提取成绩并构建以学号为键的哈希字典 (O(1) 查找)
    $scoresDict = [];
    if ($taskRe->scores) {
        foreach ($taskRe->scores as $score) {
            $scoresDict[$score->sc_stu] = $score;
        }
    }
```

```php
/**
 * 显示学生的成绩单
 * @return string json字符串
 */
public function getStuScore()
{
    try {
        // 步骤1：从 JWT 认证信息中获取当前登录学生的学号 (stu_id)
        // jwtUser 是 JWT 中间件解析后注入到 request 对象中的用户信息
```

# 第 38 页：模型方法设计：Score.php/getScore（第 1 部分：关联与学期过滤）

```php

 * 获取学生的某些成绩

 * @param array $params ['taskId', 'startTerm', 'endTerm']
 * @param int $limit
 * @return array 成绩列表

public function getScore($stuId, $params, $limit = 15)
{
    // 1. 构建基础查询链：深度预载入成绩关联的任务、课程、教师、学生信息

        $params['startTerm'] = TermTool::thisTerm();

    } else {
        // 2.2 传入区间，利用闭包穿透查询学期范围
        $scores = $scores->hasWhere('taskInfo', function ($query) use ($params) {
            $query->where('ta_term', 'between', [$params['startTerm'], $params['endTerm']]);
        });
    }
```
