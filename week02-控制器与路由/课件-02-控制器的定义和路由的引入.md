# 第 4 页：什么是控制器——controller

### 控制器定义
* 按照 ThinkPHP 的架构设计，所有的 URL 请求（无论是否采用了路由），最终都会定位到控制器（也许实际的类不一定是控制器类，但也属于广义范畴的控制器）。控制器的层可能有很多，为了便于区分就把通过 URL 访问的控制器称之为**访问控制器**（通常意义上我们所说的控制器就是指访问控制器）。
* ThinkPHP 的控制器定义比较灵活，可以**无需继承任何的基础类**，也或者根据业务需求封装自己的基础控制器类。

# 第 5 页：控制器文件（单应用 or 多应用）

### 单应用模式
```php
<?php
namespace app\controller;

class UserController
{
    public function login()
    {
        return 'login';
    }
}
```
* 相应的控制器类文件位置：`app\controller\UserController.php`

### 多应用模式（多层/子目录控制器）
```php
<?php
namespace app\index\controller\user;

class Blog
{
    public function index()
    {
        return 'index';
    }
}
```
* 该控制器类的文件位置：`app/index/controller/user/Blog.php`
* 访问地址可以使用：`http://serverName/index.php/user.blog/index`

# 第 6 页：创建 User 控制器（多应用模式）

### 2.2.1 创建 User 控制器
* **场景**：在 `edu` 应用中创建 `User` 控制器，处理用户相关的请求（登录、注册、用户信息查询及修改等）。
* **步骤**：
  1. 使用命令行生成控制器文件；
  2. ThinkPHP 8 提供了内置的命令行工具，可以快速生成控制器代码骨架，无需手动创建文件和编写基础结构；
  3. 打开命令行终端，切换到项目根目录（包含 `think` 文件和 `app/` 目录的那一层），执行以下命令：
     ```bash
     php think make:controller edu@User
     ```
* **命令说明**：
  * `make:controller` 是创建控制器的指令。
  * `edu@User` 表示在 `app/edu/controller/` 目录下生成 `User.php` 控制器文件。
  * 命令行会自动识别多应用模式下的目录结构，生成对应的命名空间。
  * 执行成功后，命令行会提示控制器创建成功，并显示生成的文件路径。

# 第 12 页：帮助文档——路由

### 路由的作用（包括但不限于）：
* 让 URL 更规范以及优雅；
* 隐式传入额外请求参数；
* 统一拦截并进行权限检查等操作；
* 绑定请求数据；
* 使用请求缓存；
* 路由中间件支持。

### 路由解析的过程一般包含：
* 路由定义：完成路由规则的定义和参数设置；
* 路由检测：检查当前的 URL 请求是否有匹配的路由；
* 路由解析：解析当前路由实际对应的操作（方法或闭包）；
* 路由调度：执行路由解析的结果调度。

> 掌握路由主要是要掌握路由定义及参数设置，其它环节是由系统自动完成的。路由的主体规则和定义应该尽可能在应用开发前完成。

---

# 第 13 页：引入路由的好处

* **美化 URL**：将 `edu/user/login` 变为 `sessions` 或 `logging`，更加简洁；
* **安全控制**：隐藏真实的控制器名，防止未授权访问；
* **参数校验**：在路由层直接限制参数类型；
* **多应用支持**：不同应用可拥有独立的路由定义文件。

---

# 第 14 页：路由解析的过程

1. **第一步（人工）**：**路由定义** —— 完成路由规则定义和参数的设置。
2. **第二步（系统自动）**：**路由检测** —— 检查当前的 URL 请求是否有匹配的路由。
3. **第三步（系统自动）**：**路由解析** —— 解析当前路由实际对应的操作。
4. **第四步（系统自动）**：**路由调度** —— 执行路由解析的结果调度。

# 第 19 页：步骤 2：注册路由

### 基础注册方法
```php
Route::rule('路由表达式', '路由地址', '请求类型');
```

要使用 `Route` 类注册路由必须首先在路由定义文件开头添加引用：
```php
use think\facade\Route;
```

### 示例（假设为单应用模式）
```php
// 注册路由到 News 控制器的 read 操作
Route::rule('new/:id', 'News/read');
```
* **访问方式**：`http://serverName/new/5`（有效地址）
* **系统自动定位到**：`http://serverName/news/read/id/5`
* **注意**：在**强制路由模式**下，原实际地址自动失效。

# 第 23 页：路由参数绑定与变量规则

### 动态路由定义
可以把路由规则中的变量传入路由地址中，实现动态路由，例如：
```php
// 定义动态路由，name 变量的值作为路由地址传入
Route::get('hello/:name', 'index/:name/hello');
```

### 变量规则限制示例
```php
<?php
use think\facade\Route;

// 限制 id 必须为数字
Route::get('user/:id', 'User/info')->pattern(['id' => '\d+']);

// 限制 id 必须为 5 位数字
Route::get('user/:id', 'Article/info')->pattern(['id' => '\d{5}']);

// 限制 id 为数字，name 为字母
Route::get('user/:id/name/:name', 'User/detail')
    ->pattern(['id' => '\d+', 'name' => '[a-zA-Z]+']);
```

# 第 27 页：总结：路由表达式

* **静态地址**：不包含动态参数的地址。
  * 示例：`my`、`/`、`hello`
* **动态地址**：包含动态参数的地址。
  * 必选参数：`/:id`、`/:x/:y`、`/<sid>`（建议）
  * 可选参数：`/[:id]`、`/<mid?>`
* **静态地址 + 动态地址**：既包含静态地址，也包含动态参数。
  * 示例：`my/<id>`、`show/<x>/<y?>`

# 第 28 页：路由分组管理

### 路由分组概念
路由分组功能允许把相同前缀的路由定义合并分组，这样可以简化路由定义，并且提高路由匹配的效率，不必每次都去遍历完整的路由规则（尤其是开启了路由延迟解析后性能更佳）。

### 使用 `Route::group` 注册分组
```php
Route::group('blog', function () {
    Route::rule(':id', 'blog/read');
    Route::rule(':name', 'blog/read');
})->ext('html')->pattern(['id' => '\d+', 'name' => '\w+']);
```

### 分组常用链式操作方法及描述

| 方法 | 描述 |
| :--- | :--- |
| `prefix` | 设置分组的路由地址前缀 |
| `mergeRuleRegex` | 设置当前分组的路由合并解析 |
| `dispatcher` | 设置分组的调度 |
| `layer` | 分组绑定到控制器分级（V8.1.0+） |
| `namespace` | 分组绑定到命名空间（V8.1.0+） |
| `controller` | 分组绑定到控制器（V8.1.0+） |
| `class` | 分组绑定到类（V8.1.0+） |
| `auto` | 开启分组自动 URL 调度（V8.1.0+） |

# 第 34 页：标准的返回格式

### 推荐的标准返回格式代码
```php
// 推荐的标准返回格式
```

# 第 37 页：路由模式——普通模式

### 一、普通模式
关闭路由，完全使用默认的 `PATH_INFO` 方式 URL：
```php
// 是否启用路由
'with_route' => false,
```
* **效果**：路由关闭后，不会解析任何路由规则，采用默认的 `PATH_INFO` 模式访问 URL：
  ```text
  http://serverName/index.php/module/controller/action/param/value/...
  ```

---

# 第 38 页：路由模式——混合模式与强制模式

### 二、混合模式
开启路由，并使用路由定义 + 默认 `PATH_INFO` 方式的混合：
```php
// 是否启用路由
'with_route' => true,
// 是否强制使用路由
'url_route_must' => false,
```
* **说明**：该方式下，只需要对需要定义路由规则的访问地址定义路由规则，其它的仍然按照普通模式的 `PATH_INFO` 模式访问 URL。

### 三、强制模式
开启路由，并设置必须定义路由才能访问：
```php
// 是否启用路由
'with_route' => true,
// 是否强制使用路由
'url_route_must' => true,
```

  * 设置 `'with_route' => true`
* **应用配置文件**：`app/guirz_forum/config/route.php`

# 第 42 页：解决问题：Miss 路由

* **作用**：如果希望在没有匹配到所有的路由规则后执行一条设定的路由，可以注册一个单独的 MISS 路由：
  ```php
  Route::miss('public/miss');
  ```
* **闭包定义方式**：
  ```php
  Route::miss(function () {
      return '404 Not Found!';
  });
  ```
* **特性**：**一旦设置了 MISS 路由，相当于开启了强制路由模式**。当所有已经定义的路由规则都不匹配的话，会路由到 `miss` 方法定义的路由地址。

# 第 45 页：Miss 路由的定义和效果

### 1. 路由定义（`eduback.php`）
```php
Route::miss('Error/miss');
```

### 2. 空控制器实现（`app/eduback/controller/Error.php`）
```php
<?php
declare (strict_types = 1);

namespace app\eduback\controller;

use app\BaseController;

class Error extends BaseController
{
    /**
     * 默认方法 / 找不到miss方法，就自动调用__call方法
     * @return string json字符串
     */
    public function __call($name, $arguments)
    {
        return $this->jsonError('你访问的页面不存在');
    }
}
```

### 3. 访问效果
* 访问不存在的路径：`http://localhost:8000/eduback/www`
* 输出 JSON 响应：
  ```json
  {
    "code": 404,
    "msg": "你访问的页面不存在"
  }
  ```

# 第 46 页：Miss 路由不解决的问题

Miss 路由仅解决控制器内动作或规则匹配不到的问题，**无法解决以下输入错误**：
1. **应用名有误**：例如访问 `http://weibo.com:8080/guirz_wb/gui.html`，直接抛出 `控制器不存在:app\control` 的底层异常。
2. **端口有误**：例如 `http://weibo.com:8081/gui.html`，直接导致网络连接失败（`ERR_CONNECTION_REFUSED` / 无法访问此网站）。
3. **域名有误**：例如 `http://wb.com:8080/gui.html`，网络层拒绝连接（`ERR_CONNECTION_REFUSED`）。
